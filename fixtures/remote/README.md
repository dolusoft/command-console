# Remote fixtures

Examples of the remote contract ([`docs/remote-contract.md`](../../docs/remote-contract.md)) for any implementation of either side: the tab (command-console) and the desktop CLI. The document is normative; these files are its examples, not a replacement for it.

Each file is one JSON array or object on one topic. Every example has a `name` that is unique in its file; the name is its identity.

## Classes

| Folder or file      | Form                                                    | Meaning                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------- | ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `valid/*.json`      | `{ name, envelope, read }` or `{ name, parts, read }`   | Accepted. `read` is what the reader gets: the message `parseCliMessage` returns (unknown fields left out), the reply as the CLI reads it, or the capabilities object of the joined `parts`.                                                                                                                                                                                                                 |
| `invalid/*.json`    | `{ name, envelope, code }` or `{ name, parts, code }`   | Refused. `code` is `parseCliMessage`'s code for a message from the CLI; `invalid` for a reply or capabilities the CLI cannot read.                                                                                                                                                                                                                                                                          |
| `future/*.json`     | `{ name, direction, envelope \| parts, expect, read? }` | A message from a later version. `direction` is `cli-to-tab` or `tab-to-cli`. `expect` is `accept-ignore` (read, unknown parts ignored; `read` when given is the result), `ignore` (the whole message is dropped: an unknown `kind`), or `{ default: { path: value } }` (read with the documented default; a path is dotted, `exitCode` is the CLI's exit code).                                             |
| `sequence/*.json`   | `{ name, danger, request, replies, expect }`            | What the CLI does with a run of replies. `danger` is the command's `danger` in the capabilities; `replies` holds replies and events (`{ "event": "connection-lost" \| "timeout" \| "ctrl-c" }`) in order; `expect` is `{ exitCode, json, absent? }`, where `json` is a subset of the CLI's `--json` result and `absent` lists fields it must not have. command-console checks only their form.              |
| `error-class.json`  | `[{ code, class }]`                                     | Every `ErrorCode` and its class (C-105).                                                                                                                                                                                                                                                                                                                                                                    |
| `command-name.json` | `{ commands, rows }`                                    | The command name rule. `commands` is the tab's command set; each row has `name`, `input` (`{ argv }` or `{ line }`), `cli` (`{ name }`: the name the CLI checks and sends; or `{ refuse }`: `name` or `sensitive`), `tab` (`{ name }`: the command that runs; or `{ refuse }`: the error code) and `sensitive: true` when the tab must refuse it on the sensitive path, with no `message` and no `suggest`. |

In this repository, `packages/command-protocol/tests/remote-fixtures.spec.ts` runs `valid`, `invalid`, `future` and `error-class.json` against the protocol (C-109) and checks the form of `sequence` and `command-name.json`; from 1.7.0 the core's specs also run `command-name.json` through `attachRemote`.

## Never changed, only added

A published example is never changed or removed; a new case is a new example with a new name. From 1.7.0 each release attaches this folder and the contract document as `remote-fixtures-<version>.tar.gz`, and CI compares the folder with the latest published archive.
